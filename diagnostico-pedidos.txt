PROBLEMA 1 (BLOQUEANTE) — El INSERT en `pedido_detalles`
envía 4 columnas que NO existen
============================================================
- Problema:      El INSERT falla con PGRST204 (columna inexistente).
- Archivo:       src/App.jsx
- Líneas:        1437-1451 (dentro de `guardarPedido()`)
- Código afectado:
    .insert({
      pedido_id: pedido.id,
      producto_id: productoIdSeguro,
      variante_id: item.variante?.id ?? item.variante_id ?? null,   // ← 1442
      cantidad: item.cantidad,
      nombre_producto: item.producto.nombre,                        // ← 1444
      nombre_variante: item.variante?.nombre ?? item.nombre_variante ?? null, // ← 1445
      precio_unitario: precio,
      subtotal: precio * item.cantidad,
      observaciones: item.detalle?.trim() || null                   // ← 1448
    })
- Estructura esperada de Supabase (real):
    `producto_nombre` existe.
    `variante_id`, `nombre_variante`, `nombre_producto` y `observaciones`
    NO existen. El texto del detalle se llama `detalle`.
- Causa:          El código fue escrito contra un esquema imaginado/distinto.
                  PostgREST rechaza el INSERT completo con:
                  "PGRST204: Could not find the 'variante_id' column of
                  'pedido_detalles' in the schema cache."
- Solución recomendada:
    * variante_id      → ELIMINAR (no hay columna de variantes)
    * nombre_variante  → ELIMINAR
    * nombre_producto  → RENOMBRAR a `producto_nombre`
    * observaciones    → RENOMBRAR a `detalle`
- Riesgo:         ALTO — sin este cambio NINGÚN pedido se puede guardar
                  (falla en el primer detalle).

PROBLEMA 3 — Pedidos huérfanos por falta de transacción
============================================================
- Problema:      Si falla un INSERT intermedio, el pedido en `pedidos` ya
                  quedó creado y queda huérfano (sin detalles).
- Archivo:       src/App.jsx
- Líneas:        1368-1588 (`guardarPedido()`)
- Código afectado:
    Secuencia INSERT: pedidos → pedido_detalles → pedido_personalizaciones
    → pedido_archivos (cada uno una request separada, sin rollback).
- Causa:          No hay transacción ni rollback; falla parcial = datos sucios.
- Solución recomendada:
    Al detectar error tras crear el pedido, intentar .delete() del pedido
    huérfano (o usar una RPC/transacción server-side a futuro).
- Riesgo:         MEDIO — datos sucios acumulados; hoy con el Problema 1 ya
                  se están creando pedidos huérfanos.

PROBLEMA 7 — Schema cache de PostgREST
============================================================

                  código esté corregido.

- Riesgo:         BAJO (solo aplica si se modifica el esquema).
